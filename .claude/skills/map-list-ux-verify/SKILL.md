# 지도/목록 레이아웃 변경 — 불변식과 검증 절차

이 영역은 **눈으로 확인하지 않고 커밋해서 두 번 되돌린 이력**이 있다.

```
085bb10 Revert "feat: 목록 흰 박스를 끌어내려도 시트가 닫힌다"
dd2964a Revert "feat: 지도 하단 중앙의 목록 버튼으로 '목록만 보기'"
```

논리적으로 맞는 변경이 실제 화면에서는 틀린다. 지도·시트·오버레이가 서로를 가리고,
컨테이너 크기 변화가 지도 내부 상태를 흔들기 때문이다. 그래서 이 영역만큼은
**고친 다음 반드시 브라우저에서 확인하고, 확인한 근거(스크린샷)를 남긴다.**

## 1. 고치기 전에: 이 결정들은 의도된 것이다

코드에 남은 아래 제약은 실수가 아니라 판단의 결과다. 바꾸려면 **왜 그렇게 정했는지
먼저 읽고**, 바꾼 뒤에는 그 근거 주석도 함께 갱신한다.

| 제약 | 위치 | 이유 |
| --- | --- | --- |
| `SNAP.open = 0.42` | `BottomSheet.jsx` | 헤더를 감안하면 본문 기준 0.42가 **휴대폰 화면의 약 절반**이다. 지도가 화면 절반 아래로 내려가면 지도 앱이 아니게 된다 |
| `MAX_RATIO = 0.45` | `BottomSheet.jsx` | 드래그로도 그 이상 못 올리게 막은 것 |
| `SNAP.closed = 0` | `BottomSheet.jsx` | 완전히 사라져 지도만 남는 상태. 높이가 0이라 **손잡이도 없어진다** |
| 지도 하단 중앙 목록 버튼 | `App.jsx` | `closed`에서 목록으로 돌아오는 **유일한 길**. 지우면 복귀 불가 |
| 위치 요약을 스크롤 영역 안에 | `App.jsx` | 밖에 고정하면 시트를 올릴 때 제자리에 남아 어색하다 |
| 탭 칩 왼쪽 정렬 | `App.jsx` | 가운데 정렬하면 지도의 가장 중요한 부분(중심) 바로 위를 가로지른다 |

**비율을 올릴 때는 반드시 실제 기기 높이로 다시 계산한다.**
예: 812px 화면 · 헤더 47px → 본문 765px · 시트 321px → 지도 444px(화면의 55%).

## 2. 불변식 체크리스트

레이아웃을 바꾼 뒤 아래가 전부 참인지 확인한다. 하나라도 깨지면 되돌릴 후보다.

**복귀 가능성 (가장 중요)**
- [ ] 어떤 상태에서도 **반대편으로 돌아갈 길이 화면에 보인다.** 지도만 남으면 목록 버튼이,
      목록만 남으면 지도로 가는 손잡이나 버튼이 있어야 한다. 높이 0인 시트는 손잡이도 없다는
      것을 잊지 말 것
- [ ] 새로고침 없이 초기 상태로 돌아올 수 있다

**지도가 지도로 남는가**
- [ ] 기본 상태에서 지도가 **화면의 절반 이상**이다 (본문 기준이 아니라 화면 기준)
- [ ] 선택한 마커가 시트/오버레이 뒤에 숨지 않는다
- [ ] 검색창·탭 칩이 지도 중심을 가로지르지 않는다

**클릭이 통과하는가**
- [ ] 지도 위 오버레이 컨테이너는 `pointer-events-none`, 실제 컨트롤만 `pointer-events-auto`
- [ ] 오버레이를 비껴간 클릭이 지도에 그대로 닿는다 (지도 배경 클릭 = 선택 해제)

**지도 내부 상태**
- [ ] 시트를 움직인 뒤에도 지도 축척이 튀지 않는다 (컨테이너 크기 변화 → `relayout`)
- [ ] `bottomInsetRatio`가 새 스냅 값과 맞다. 시트가 화면 대부분을 덮는 스냅을 추가했다면
      inset 보정(`panTo`·`setBounds`)이 무의미해지거나 뒤집히지 않는지 확인한다
- [ ] 회전·주소창 접힘 후에도 보던 화면이 유지된다

**데스크톱**
- [ ] `lg` 이상에서 시트 드래그 핸들러가 붙지 않는다 (`enabled={!isDesktop}`)
- [ ] 목록 전용 컨트롤이 데스크톱에서 중복 노출되지 않는다

## 3. 브라우저 검증 절차

`.claude/launch.json`에 `open-med-finder`(포트 5173)가 정의되어 있다.

1. `preview_start` — `{ name: "open-med-finder" }`
2. **모바일 먼저** — `resize_window` `{ preset: "mobile" }` (375×812). 모바일이 이 앱의
   주 사용 환경이고, 시트는 모바일에서만 켜진다
3. 각 스냅 상태를 실제로 만들어 본다. 드래그는 `computer`의 `left_click_drag`로,
   손잡이 좌표에서 위/아래로 끈다. 버튼 경로도 눌러본다
4. 상태마다 `computer {action:"screenshot"}` — 이게 사용자에게 보여줄 근거다
5. `read_console_messages` `{ onlyErrors: true }`로 지도 오류를 확인한다
6. **데스크톱** — `resize_window` `{ preset: "desktop" }` 로 2단 레이아웃 회귀 확인
7. 끝나면 `resize_window` `{ preset: "desktop" }` 로 크기 에뮬레이션을 되돌린다

검증할 상태 조합(최소):

| # | 화면 | 상태 | 볼 것 |
| --- | --- | --- | --- |
| 1 | 모바일 | 기본(`open`) | 지도가 화면 절반 이상인가 |
| 2 | 모바일 | 시트를 끝까지 내림(`closed`) | 목록 복귀 버튼이 보이는가 |
| 3 | 모바일 | 마커 선택 | 선택한 핀이 시트 뒤로 숨지 않는가 |
| 4 | 모바일 | 상세 열림 | 지도가 남아 있고 뒤로 갈 수 있는가 |
| 5 | 데스크톱 | 기본 | 2단 레이아웃이 그대로인가 |

새 상태(전체화면 스냅 등)를 추가했다면 그 상태와 **그 상태에서 빠져나오는 경로**를
표에 추가해 함께 확인한다.

## 4. 사용자에게 보고할 때

"확인해 보세요"라고 넘기지 않는다. 스크린샷을 직접 보여주고, 불변식 체크리스트 중
무엇을 확인했는지 말한다. 특히 **바꾸면서 함께 옮긴 판단**(예: "지도 절반 규칙을
0.42에서 0.55로 올렸습니다 — 화면 기준으로는 여전히 45%입니다")은 명시한다.
그래야 사용자가 되돌릴지 판단할 수 있다.

## 5. 되돌릴 때

이 영역은 되돌리는 것이 부끄러운 일이 아니다. 다만 **왜 되돌렸는지**를 커밋 메시지나
코드 주석에 남긴다. 같은 아이디어가 몇 주 뒤에 다시 올라오기 때문이다.
기존 주석들이 "지우면 안 되는 이유"를 적어둔 것도 같은 목적이다.

커밋 메시지는 이 저장소 관례를 따른다 — 한국어로, **사용자가 체감하는 변화**를 쓴다.
`fix: z-index 조정`이 아니라 `fix: 목록이 지도를 덮어버리던 문제`.

## 이 저장소에서 실제 코드 위치

| 내용 | 파일 |
| --- | --- |
| 스냅 정의·드래그·높이 계산 | `src/components/BottomSheet.jsx` |
| 레이아웃·오버레이·목록 복귀 버튼 | `src/App.jsx` (본문 렌더 부분) |

| 개발 서버 설정 | `.claude/launch.json` |

지도 내부 동작(relayout·panTo·마커)을 함께 건드린다면 `kakao-map-integration` 스킬도 읽는다.
